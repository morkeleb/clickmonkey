# V-15 — pointer-events none

**Chapter:** visual  
**Rule:** `pointerEvents`  
**Spec:** [pointer-events none](https://morkeleb.github.io/clickmonkey/findings/V-15/)

The control is shown and enabled but pointer-events is none, so a mouse click never hits it.

Keyboard may still focus it. Disabled/aria-hidden and a child with auto under a none parent are not this.

This id is **stable**. Reports link here so T/V/Q classes (and A-2.1.1) do not shuffle when a soak ranks differently.
